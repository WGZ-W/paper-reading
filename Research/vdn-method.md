如果研究的是“导航过程中，人类不等智能体提问，而是主动补充、纠正或更新指令”，最合适的定位不是传统 VDN，而是：

> Human-initiated / Mixed-initiative Vision-Language Navigation  
> 人主动干预的混合主动式视觉语言导航。

我建议采用“DialNav 的交互框架 + I3L 的语言干预思想 + 在线重规划”的组合，而不要直接套用 CVDN/NDH。

## 1. 最值得参考的几类方案

### 第一类：VNLA / HANNA——把中途指令视为语言子目标

VNLA 将人类帮助建模为“间接干预”：人不直接控制动作，而是给出类似“向前走三步，然后左转”的语言子目标。I3L 则研究如何让智能体在执行过程中利用这种额外信息。[VNLA/I3L，CVPR 2019](https://arxiv.org/abs/1812.04155)

HANNA 在此基础上加入记忆和分层控制，把人类给出的指令作为临时子任务执行，完成后再恢复原始目标。[HANNA](https://arxiv.org/abs/1909.01871)

它们与目标最接近的部分是：

- 中途插入新的语言指令；
- 原始目标与临时子目标分层管理；
- 人类指令只影响决策，不直接接管机器人。

局限是它们仍以“智能体请求帮助”为主。你的研究需要把触发权从 agent 侧移到 human 侧。

### 第二类：自然语言计划纠正——把新指令解释成计划修改

《Correcting Robot Plans with Natural Language Feedback》将人类的中途话语解析为：

- 修改目标；
- 增加约束；
- 删除约束；
- 指定必经点；
- 调整路径偏好。

然后直接变换规划器的目标函数或约束，而不是简单拼接文本。[Correcting Robot Plans，RSS 2022](https://arxiv.org/abs/2204.05186)

这非常适合“不要走左边，那里被堵住了”“先去门口”“不是红色沙发，是蓝色沙发”一类主动纠正。

### 第三类：Mixed-Initiative Control——允许人随时插入任务

Human-in-the-Loop Mixed-Initiative Control 允许人类在运行过程中主动：

- 修改导航输入；
- 添加临时任务；
- 改变路径偏好；
- 在安全约束下接管部分决策。

其优点是对“谁拥有发言权、何时修改计划”定义得比较清楚。[Mixed-Initiative Control，ICRA 2018](https://arxiv.org/abs/1802.06839)

它不是视觉语言学习方法，但非常适合用来构建你的任务形式和安全机制。

### 第四类：DialNav——参考完整交互系统与远程 Guide

DialNav 的 Navigator、Guide、定位、问答和导航闭环很完整，而且 Guide 不知道 Navigator 的真实位置，必须从对话中推断。[DialNav，ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/papers/Han_DialNav_Multi-turn_Dialog_Navigation_with_a_Remote_Guide_ICCV_2025_paper.pdf)

你可以修改它的交互协议：

- 原版：Navigator 提问 → Guide 回答；
- 你的版本：Guide 可以在任意时刻主动发出指导；
- 完整版本：Navigator 可以提问，Guide 也可以主动提醒，即 mixed-initiative。

### 第五类：MICoBot——参考双方主动发起对话的架构

MICoBot 面向移动操作而非纯导航，但其三层架构很值得借鉴：

1. 元规划器理解人机对话；
2. 任务规划器修改后续步骤；
3. 执行器产生物理动作或语言回复。

人和机器人都可以主动建议、拒绝、确认和重新协商。[MICoBot，ICRA 2026](https://arxiv.org/abs/2508.05535)

## 2. 推荐的任务定义

建议将任务定义为“事件驱动的混合主动式导航”：

```text
初始目标 I₀
   ↓
视觉观察 + 轨迹/地图记忆
   ↓
当前导航计划 Pₜ
   ↓
人类可在任意时刻发出消息 mₜ
   ↓
识别消息类型和作用范围
   ↓
更新目标、约束或子目标
   ↓
重新规划并继续执行
```

在时刻 \(t\)，智能体维护：

\[
b_t = f(b_{t-1}, o_t, a_{t-1}, m_t)
\]

其中：

- \(o_t\)：当前视觉观察；
- \(a_{t-1}\)：上一动作；
- \(m_t\)：可为空的人类主动指令；
- \(b_t\)：当前环境、目标和人类意图的联合信念。

这里的关键不是把 \(m_t\) 拼接到历史文本后面，而是把它转换成一个结构化的“计划增量”：

\[
\Delta_t = (\text{type},\text{target},\text{constraint},
\text{validity},\text{priority})
\]

例如：

| 人类话语 | 类型 | 结构化更新 |
|---|---|---|
| “前面左转” | 新子目标 | 插入左侧相邻节点 |
| “别进厨房” | 路径约束 | 禁止厨房区域 |
| “你走错了，退回刚才的门口” | 纠错 | 回退到历史节点 |
| “目标其实是蓝色沙发” | 目标细化 | 更新目标属性 |
| “先停一下” | 安全指令 | 中止当前动作 |
| “不用去卧室了，去阳台” | 目标替换 | 使旧目标失效 |

## 3. 模型架构建议

比较稳妥的系统不是纯端到端，而是四个模块。

### 3.1 人类指令事件解析器

输入当前话语、对话历史、视觉状态和当前计划，输出：

- `ADD_SUBGOAL`
- `CORRECT_ROUTE`
- `ADD_CONSTRAINT`
- `REMOVE_CONSTRAINT`
- `REFINE_TARGET`
- `REPLACE_GOAL`
- `STOP/PAUSE`
- `INFORMATION_ONLY`

可以用小型 Transformer 微调，也可以先用 MLLM 生成结构化 JSON。

### 3.2 版本化指令记忆

保存每条指令的状态：

- active；
- completed；
- superseded；
- cancelled；
- uncertain。

优先级建议为：

\[
安全指令 > 最新明确纠正 > 新子目标 > 初始路线描述
\]

这能解决“先说左转，后来又说不要左转”之类的冲突。仅使用对话拼接通常很难可靠处理否定和指令覆盖。

### 3.3 空间信念与拓扑记忆

将人类语言中的：

- 地标；
- 房间；
- 相对方向；
- 已访问位置；
- 禁止区域；
- 临时目标

写入拓扑图或语义地图。可以基于 HAMT、DUET 等导航器，但要增加指令状态和约束表示。

### 3.4 事件触发重规划器

新指令到达时，模型需要决定：

- 继续当前动作；
- 局部调整；
- 回退；
- 完全重新规划；
- 因冲突或歧义而向人确认。

为了安全，`STOP`、避障、禁区等指令应由确定性安全层优先处理，而不是完全交给语言模型。

## 4. 数据集怎样构建

### 低成本起步方案

以 R2R、CVDN 或 DialNav 的轨迹为基础：

1. 让基础导航器执行并产生偏航轨迹；
2. 在岔路口、重复探索、目标混淆或错误动作后插入干预点；
3. 向标注者展示当前全景、历史轨迹和目标；
4. 让标注者自由决定是否主动发送指令；
5. 记录指令、时间点、修改后的动作和最终结果。

LLM 可以生成训练集初稿，但验证集和测试集最好使用真实人类话语。

### 更有研究价值的采集方案

让人类监督者实时观察智能体：

- 人可以保持沉默；
- 可以随时主动提醒或纠正；
- 不设置固定干预位置；
- 智能体可以接受、拒绝或请求确认；
- 记录人类为什么选择此时干预。

建议设置两种 Guide：

- **全知监督者**：看到地图、目标和智能体位置；
- **远程非全知监督者**：只看到部分视图或低频位置更新。

后者更真实，也更接近 DialNav。

为了获得足够的主动干预，可以在采集阶段有控制地制造：

- 错误转弯；
- 目标属性混淆；
- 道路阻塞；
- 动态目标变化；
- 新的安全约束。

否则强导航器可能很少犯错，导致人类主动指令数据过于稀疏。

## 5. 应设置的基线

至少比较以下五个基线：

1. **No-intervention**：忽略中途人类指令。
2. **Text-concat**：把新指令简单拼接到对话历史。
3. **Latest-only**：收到新指令后只执行最新话语。
4. **Memory navigator**：HAMT/DUET 类长历史导航器。
5. **Structured-update**：指令解析、版本化记忆和重规划的完整方法。

其中 Text-concat 是非常重要的基线：它可以证明结构化更新是否真的优于“把所有内容交给大模型”。

## 6. 评测指标

除了 SR、SPL、NE 和 nDTW，建议增加：

- **Intervention Gain**：有人主动指导相对无指导的成功率提升；
- **Recovery Rate**：收到纠正后从错误状态恢复的比例；
- **Instruction Compliance**：轨迹满足新指令或约束的比例；
- **Response Latency**：收到指令到行为发生改变的动作步数；
- **Human Effort**：干预次数、词数和交互时间；
- **Unnecessary Replanning**：本不需要却重新规划的比例；
- **Conflict Resolution Accuracy**：新旧指令冲突时的处理准确率；
- **Unsafe Override Rate**：错误语言是否覆盖了安全约束；
- **Robustness**：面对延迟、错误、含糊或相互矛盾指令时的表现。

最好对同一初始状态进行成对实验：

\[
\text{Intervention Utility}
=
R(\text{with intervention})
-
R(\text{counterfactual no intervention})
\]

否则很难判断成功是来自人类指令，还是智能体本来就能完成。

## 7. 最推荐的研究切入点

如果目标是形成一篇相对明确的研究工作，我最推荐：

> 基于 DialNav/Matterport3D 构造 Human-Initiated Navigation：允许远程 Guide 在任意时刻主动补充或纠正指令；模型将自由语言转换成可撤销、可覆盖的空间约束，并触发局部重规划。

这个切入点有几个优势：

- 与现有“智能体主动提问”明显不同；
- 可以复用成熟导航器和仿真环境；
- 新贡献集中在主动干预、指令冲突和在线重规划；
- 容易设置 text-concat、latest-only 等清晰基线；
- 后续可以自然扩展成双方都能发起交流的 mixed-initiative 系统。

不建议第一步就做完全开放的人机长对话和真实机器人。先在离散 Matterport3D 环境验证“主动指令事件是否能够被正确接收、覆盖和执行”，再扩展到 Habitat 连续控制和真实机器人，会更容易得到可解释的研究结论。
