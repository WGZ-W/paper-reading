# 视觉—语言导航中的混合主动权：研究背景、核心问题、方法与数据集

> 更新时间：2026-09-10  
> 内容依据：[视觉—语言导航中的人机交互发展综述](./vln-human-computer-interaction.md)。本文是在该综述基础上的问题归纳与研究方案设计；其中“建议”“可采用”描述的是研究设想，不代表已有工作已经完整实现。

## 1. 核心概念

视觉—语言导航（VLN）中的**混合主动权（mixed-initiative）**，是指人和智能体都能在任务执行过程中主动发起交互，并且交互的主导权可以随状态变化在双方之间切换：

- 智能体发现信息不足、风险过高或能力受限时，可以询问、确认、解释或请求接管；
- 人无需等待智能体提问，可以随时补充地标、纠正路线、改变目标、增加约束、要求暂停或直接接管；
- 系统需要理解这次介入与当前任务的关系，把有效信息落实到目标信念、地图、规划和动作中。

它不等同于一般的多轮对话。一个系统即使能读取很长的对话历史，如果只能被动执行、不能主动询问，也不能正确处理人临时插入的指导，就不具备完整的混合主动权。反过来，混合主动权也不要求机器人持续聊天；一次及时的纠正、确认或紧急停止同样是关键交互。

可以将它概括为以下闭环：

**理解初始意图 → 行动与观察 → 接收人的随时指导或估计自身不确定性 → 选择继续、询问、确认、暂停或接管 → 融合新信息 → 安全重规划 → 汇报结果。**

## 2. 研究背景

### 2.1 从单向指令到双向协作

VLN 的早期设定通常假设：人一次性给出完整、准确的路线指令，随后退出任务，智能体只负责理解和执行。这种设定便于建立标准化 benchmark，但忽略了真实使用中的几个事实：

- 普通用户可能省略地标、混用方向或只知道目标，不知道完整路线；
- 环境、任务目标和安全约束可能在执行过程中发生变化；
- 人能够观察智能体行为，并在它明显走错之前主动纠正；
- 智能体也可能识别到自己的信息边界，需要向人请求最有价值的帮助。

相关研究随后经历了“请求帮助—读取对话历史—长程任务协作—主动询问—反馈适应—开放式长时程交互”的演进。HANNA、Just Ask 等工作开始研究智能体何时求助；CVDN、NDH-Full 将对话历史纳入导航；TEACh 将对话与导航、物体操作和执行中纠错结合；To Ask or Not to Ask、ELBA、CoIN 进一步研究何时问、问什么以及如何减少用户负担；ATENA 则表明人的成功/失败反馈还可用于测试时适应。

不过，这条研究脉络主要围绕“智能体发问—人回答”展开。真实的人机协作还存在相反方向的主动性：人会根据任务进展随时介入。混合主动权因此将研究对象从单一的**询问策略**扩展为完整的**双向交互与控制权协调问题**。

### 2.2 为什么需要混合主动权

混合主动权的价值主要来自四个方面：

1. **弥补信息不对称。** 智能体拥有实时视觉与局部地图，人拥有任务意图、偏好、常识或远程视角，双方掌握的信息不同。
2. **提高错误恢复能力。** 人可在发现误解、定位漂移或路线错误时立即纠正，而不必等待智能体先意识到问题。
3. **适应动态任务。** 用户可能临时改变目的地、加入“不要走楼梯”等约束，环境中也可能出现新的障碍或风险。
4. **保持人的最终控制权。** 在家庭、公共空间和无人机场景中，暂停、拒绝、接管和安全确认不是附加功能，而是可信部署的基本条件。

### 2.3 研究目标

这一问题不应只优化导航成功率，而应在任务效果、用户负担和安全风险之间寻找平衡。可将总体目标写成：

> 在人的有限注意力和系统安全约束下，使人或智能体在最有价值的时刻取得交互主动权，并确保新信息能够被正确理解、验证和落实到后续行为。

因此，系统需要同时优化：

- 任务是否完成、路径是否高效；
- 智能体是否只在值得询问时打断用户；
- 人的主动指导是否被及时、正确地执行；
- 面对冲突、错误或危险指令时是否能安全处理；
- 控制权切换是否清楚、可预测且可追责。

## 3. 核心研究问题

### 3.1 谁应在什么时候取得主动权

智能体需要决定何时继续自主行动，何时询问、确认、暂停或请求接管；同时，系统必须持续监听人的介入，而不能只在预设对话轮次接收输入。

这里的难点是，动作分布熵高并不一定意味着必须询问，人的每次插话也不一定要求立刻改变路线。系统应判断新信息是否与当前决策相关、是否紧急，以及交互收益能否覆盖时间和认知成本。

### 3.2 如何理解人的主动介入

人的介入至少包括以下类型：

| 类型 | 示例 | 系统应产生的影响 |
|---|---|---|
| 补充信息 | “门旁边还有一盆植物” | 更新地标或目标信念 |
| 路线纠正 | “刚才走过头了，回到前一个路口” | 修正定位并重规划 |
| 目标变更 | “不用去厨房了，改去书房” | 替换任务目标并终止旧计划 |
| 新增约束 | “不要走楼梯” | 更新可行路径与能力约束 |
| 风险提醒 | “前面地面很滑” | 提高局部风险并调整控制策略 |
| 暂停或恢复 | “先停一下”“继续走” | 改变执行状态，但保留任务上下文 |
| 接管或交还 | “我来控制”“现在你继续” | 显式切换控制权 |
| 评价反馈 | “这次找对了”“你刚才理解错了” | 更新置信度、记忆或适应策略 |

系统不仅要做意图分类，还要完成指代消解、空间落地和时间对齐。例如，“左边那个门”必须关联到用户发话时的场景，而不一定是语句处理完成后的当前视野。

### 3.3 如何处理新旧信息冲突

主动指导可能与初始目标、历史对话、地图观察或其他用户的话互相矛盾。系统需要判断：

- 新话语是在补充旧指令，还是明确覆盖旧指令；
- 冲突来自用户改变意图、智能体理解错误，还是用户本身记错；
- 当前动作能否安全中止，是否需要先减速或停下再确认；
- 多个用户意见不一致时，谁拥有修改目标或接管的权限。

因此，简单把最新一句话拼接到语言模型上下文中是不够的。系统需要显式表示目标、约束、信息来源、时间和有效范围。

### 3.4 如何把语言真正落实到行为

“会回答”或“会复述”不代表“会协作”。收到指导后，智能体应当更新目标信念、语义地图或路径约束，并生成与指导一致的新计划。研究需要验证新话语是否对行为产生因果影响，而不能只评价生成文本是否流畅。

### 3.5 如何兼顾实时性与安全

移动机器人和无人机不能在处理长对话时停止避障。高层语言推理、低层控制和人的异步介入可能以不同频率发生。系统需要明确：

- 等待回答时是停车、减速、悬停，还是继续在已知安全区域探索；
- 收到“停下”或高风险提醒时，低层控制器能否绕过语言模型立即响应；
- 当前动作不可瞬间中止时，系统如何进入最小风险状态；
- 用户要求与安全规则冲突时，系统何时拒绝并解释。

### 3.6 如何适应真实用户差异

用户在空间表达习惯、语言能力、耐心、注意力和身体能力上存在差异，也可能提供含糊、错误、延迟甚至相互矛盾的信息。系统既要逐渐学习个体偏好，又不能把一次偶然表达固化为长期记忆。

### 3.7 如何评价混合主动权

传统 SR、SPL 和导航误差只能评价结果，不能说明交互是否有效。混合主动权还要回答：智能体是否在正确时机提问、人能否顺利介入、指导是否被落实、控制权是否清晰，以及这些收益消耗了多少用户注意力。

## 4. 建议的方法框架

### 4.1 总体架构

一个完整系统可以由以下模块组成：

| 模块 | 功能 | 关键输出 |
|---|---|---|
| 多模态状态估计 | 融合视觉、位姿、地图、动作和对话历史 | 当前状态与多类型不确定性 |
| 异步交互管理 | 持续接收人主动输入，同时管理智能体提问 | 带时间戳的交互事件 |
| 介入意图理解 | 识别补充、纠正、改目标、约束、暂停和接管 | 意图、对象、作用范围与紧急度 |
| 语言—空间接口 | 将话语转为对象、区域、方向、拓扑或几何约束 | 可验证的结构化约束 |
| 主动权策略 | 决定继续、询问、确认、暂停、拒绝或交接控制 | 交互动作与控制权状态 |
| 冲突与权限管理 | 比较新旧信息并检查用户权限、安全规则和可达性 | 接受、覆盖、澄清或拒绝 |
| 信念更新与重规划 | 更新目标、地图和计划 | 新路径或新的任务状态 |
| 安全控制器 | 高频避障、紧急停止和最小风险控制 | 可安全执行的低层动作 |
| 交互记忆 | 保存稳定偏好与关键任务变化 | 可纠正、可遗忘的用户记忆 |
| 解释与汇报 | 说明理解结果、计划变化和无法执行的原因 | 面向用户的简短反馈 |

关键设计原则是：**语言模型负责语义理解和低频规划，确定性的安全控制器负责高频避障和紧急动作。** 人的紧急停止或接管请求不应等待完整的大模型推理链路。

### 4.2 多类型不确定性建模

系统应区分不同风险来源，而不是只用一个置信度：

- 语言歧义：目标或路线表述不清；
- 目标混淆：多个对象与描述相似；
- 视觉不确定性：遮挡、光照或相似地标；
- 定位不确定性：智能体不知道自己在哪里；
- 地图不确定性：环境已经变化或区域尚未探索；
- 控制与能力不确定性：路径在几何上存在，但机器人无法安全通过；
- 用户意图不确定性：用户可能已经改变目标或新指导与历史冲突。

不同不确定性应触发不同交互。例如，目标混淆适合询问属性，定位错误适合请求地标或返回已知位置，能力受限则应说明原因并协商替代路线。

### 4.3 基于信息价值的主动权决策

智能体发起询问时，可综合考虑：

- 询问后任务成功率的预期提升；
- 风险能够下降多少；
- 用户响应所需的时间和认知负担；
- 回答可能错误、延迟或无法获得的概率；
- 不询问而继续探索的代价。

人的主动介入则应根据紧急度、权限、与当前决策的相关性和潜在影响进行处理。可采用以下基本规则：

1. **紧急停止、明确接管和即时安全提醒：** 优先进入安全状态，再进行语义确认；
2. **低风险且可逆的补充或纠正：** 更新约束并执行，同时简短确认；
3. **目标变更、高影响或与历史冲突的指令：** 先确认理解，再终止旧计划和重规划；
4. **不可行或违反安全约束的指令：** 拒绝直接执行，解释原因并提出替代方案；
5. **含糊、权限不明或多方冲突的指令：** 暂停相关动作并请求澄清。

### 4.4 可验证的语言—空间表示

可将每次有效指导转换为结构化记录：

```text
发起者：用户 / 智能体
意图：补充 / 纠正 / 改目标 / 加约束 / 暂停 / 接管 / 反馈
对象：目标、地标、区域、路径段或动作
空间关系：左侧、邻接、穿过、远离、返回等
时间范围：立即、下一路口、直到任务结束等
优先级与权限：建议、强约束、安全命令、控制权切换
置信度与证据：语言解析置信度、视觉对应、历史一致性
```

结构化表示使系统能够在执行前检查指代是否唯一、约束是否冲突、路径是否可达，并在失败后追溯是哪条信息影响了规划。

### 4.5 异步重规划与控制权状态机

系统应维护显式控制状态，例如：

```text
自主执行 ↔ 等待澄清 ↔ 安全暂停 ↔ 人工接管 ↔ 交还确认
```

收到人的介入后，不必每次从头规划整条路线。局部风险提醒可以只修改当前路径段，目标变更则需要废止旧目标并全局重规划。所有高层变化都应通过安全控制器转化为可中断、可恢复的低层动作。

### 4.6 训练方式

可采用分阶段训练：

1. **监督学习：** 学习介入类型、指代对象、结构化约束和计划变化；
2. **模仿学习：** 从人—人或人—机器人轨迹中学习何时询问、何时确认和如何响应介入；
3. **带成本的策略优化：** 联合优化任务收益、提问成本、响应延迟和安全风险；
4. **带噪用户训练：** 注入错误、含糊、延迟、拒答和目标改变，提高鲁棒性；
5. **真人校准：** 用真实用户实验修正模拟用户过于一致、耐心或全知的问题；
6. **测试时适应：** 在安全限制下利用回合成功/失败和用户纠正更新置信度，但避免灾难性遗忘。

训练时应包含反事实样本：如果去掉某次关键指导，计划是否会不同；如果把回答换成相反信息，系统能否检测冲突。这有助于防止模型只生成礼貌回应，却继续执行原计划。

## 5. 需要什么样的数据集

### 5.1 现有数据的基础与缺口

根据原综述，现有资源分别覆盖了部分能力：

| 数据或任务 | 可提供的基础 | 对完整混合主动权的主要缺口 |
|---|---|---|
| R2R 等经典 VLN | 语言—视觉—路径对齐 | 一次性指令，双方不能在线发起交互 |
| HANNA、Just Ask | 智能体请求帮助 | 助手常为 oracle 或模拟器，回答形式受限 |
| CVDN、NDH-Full | 多轮对话历史和长期一致性 | 主要读取已收集对话，不要求被测智能体在线提问 |
| TEACh | 长程任务、导航、操作和执行中纠错 | 仍需更系统地标注随时介入、控制权切换和安全响应 |
| AVDN | 异步空中对话和长路径 | 对话—轨迹对齐困难，主动权类型覆盖有限 |
| InViG | 开放式视觉指代消歧 | 不是完整导航任务 |
| CoIN、ELBA | 主动询问、开放问题和用户成本 | 重点仍是智能体发问，不完全覆盖人主动改目标或接管 |
| ATENA | 回合级反馈与测试时适应 | 反馈粒度较粗，缺少执行中介入 |
| Human-Aware VLN | 动态人类活动与社会约束 | 关注与环境中的人共处，不等同于用户—智能体双向控制 |

因此，可以在 CVDN、TEACh、AVDN 等交互基础上扩展，也可以建设专门的混合主动权 VLN 数据集。核心要求不是增加更多对话文本，而是记录**谁在什么状态下为何发起交互、交互如何改变后续计划，以及控制权怎样切换**。

### 5.2 数据集的基本单元

每个 episode 至少应包含：

| 数据层 | 建议字段 |
|---|---|
| 场景与本体 | 场景 ID、地图、动态障碍、机器人尺寸、运动与操作能力 |
| 初始任务 | 原始目标、路线描述、用户偏好、初始约束和成功条件 |
| 连续轨迹 | 时间戳、位姿、视觉/深度观察、动作、局部地图和计划版本 |
| 交互事件 | 发起者、开始/结束时间、原始话语、是否打断当前动作 |
| 介入语义 | 补充、纠正、改目标、约束、风险、暂停、接管、反馈等标签 |
| 指代落地 | 对应对象、区域、路径段、动作和有效时间范围 |
| 系统响应 | 接受、确认、澄清、拒绝、暂停、接管或交还 |
| 信念与计划变化 | 交互前后目标分布、不确定性、约束集合和路径差异 |
| 控制权状态 | 当前控制者、切换原因、切换时刻和交还条件 |
| 结果与代价 | 成功、路径长度、用时、问题数、响应延迟、碰撞或险情 |
| 人因标注 | 用户工作负荷、满意度、信任、介入必要性和系统可预测性 |

其中，**对话、观察、计划和动作必须共享时间轴**。只有保留发话时的视野、机器人位置和正在执行的动作，才能正确研究异步指导和中断处理。

### 5.3 必须覆盖的交互情形

数据集应平衡覆盖：

- 智能体主动询问、人主动介入和双方几乎同时发起交互；
- 有效补充、重复信息、无关插话、含糊指令和明确纠正；
- 目标变更、约束增加、约束撤销、暂停、恢复、接管和交还；
- 正确、部分正确、错误、延迟、拒答和互相矛盾的用户信息；
- 无需介入的顺利任务，防止模型学成频繁询问或过度响应；
- 低风险日常导航与必须立即停止的安全关键事件；
- 单用户、多用户、远程专家以及不同权限的信息源；
- 不同语言能力、空间表达习惯、注意力水平和身体能力的用户；
- 室内、室外、动态人群、长时程任务和不同机器人本体。

### 5.4 数据采集方案

建议分三层采集：

1. **受控情景采集。** 预先设计目标混淆、路线错误、动态障碍、目标改变和紧急停止等事件，确保稀有但重要的介入类型有足够样本。
2. **真人自由交互。** 让用户观察智能体实时执行，可在任何时刻说话或接管，采集自然的介入时机和表达方式。
3. **模拟扩增。** 使用规则或语言模型生成错误、延迟、拒答和表达变体，但必须用真人数据校准，且在评测集中明确区分真实与合成样本。

可采用 Wizard-of-Oz 方式收集早期数据：用户以为在与自主系统协作，后台操作者根据统一协议响应或执行，以获得自然交互，同时保证安全和可控覆盖。后续再用训练出的智能体与真人交互，形成包含真实系统失败的数据。

### 5.5 标注设计

标注不应只给对话行为标签，还应包括：

- 发起动机：不确定性、观察到错误、目标变化、风险或偏好；
- 介入意图及其紧急度、权限和预期作用范围；
- 指代对象及其在三维场景或轨迹上的落点；
- 交互前后的目标、约束、地图和计划差异；
- 系统是否正确确认、是否真正执行以及执行延迟；
- 该介入是否必要、是否有效、是否增加了额外风险；
- 冲突的来源以及正确处理方式。

部分标签可以从模拟器状态和规划器日志自动获得，但“是否自然”“是否造成负担”“是否建立恰当信任”等人因标签需要真人评价。

### 5.6 数据划分

为防止只记住场景或固定说法，至少应设置：

- 未见场景划分；
- 未见用户与表达风格划分；
- 未见介入组合，例如训练时见过“改目标”和“加约束”，测试时同时出现；
- 未见机器人能力或本体划分；
- 干净用户与带噪用户划分；
- 普通事件与安全关键事件划分；
- 真人数据与合成扩增数据的独立测试集。

还应为同一初始状态提供不同交互分支，例如“无人介入”“及时纠正”“延迟纠正”和“错误纠正”，以支持对主动权策略进行反事实比较。

## 6. 评价方案

### 6.1 任务效果

- 成功率、SPL、导航误差、完成时间；
- 错误停止、重复探索和失败恢复率；
- 接受指导前后的成功率与路径收益；
- 目标或约束改变后的重规划成功率。

### 6.2 智能体发起交互的质量

- 询问是否针对真正缺失的信息；
- 首次有效询问的时机；
- 问题数量、对话轮数和用户响应时间；
- 每次询问带来的不确定性下降和任务收益；
- 不必要询问率与遗漏询问率。

### 6.3 人主动介入的处理质量

- 介入类型、指代对象和紧急度识别准确率；
- 从发话到确认、执行和完成重规划的延迟；
- 指导落实率，以及忽略、误解或错误执行比例；
- 目标、约束和控制权切换的正确率；
- 新旧信息冲突的发现率与正确处理率。

### 6.4 行为因果性

需要验证交互是否真的改变行为：

- 去掉该轮指导后，目标信念或路径是否发生预期变化；
- 替换为相反指导后，系统能否发现冲突并避免盲从；
- 对无关插话，系统是否保持原计划而不过度反应；
- 系统口头确认的内容与后续实际动作是否一致。

### 6.5 安全与人因

- 碰撞、险情、最小人际距离和社会规范违反；
- 紧急停止延迟、接管成功率和最小风险状态到达率；
- 对危险、恶意或权限不足指令的安全拒绝率；
- 用户工作负荷、满意度、可预测性和信任校准；
- 用户能否理解当前由谁控制、为什么询问或为什么拒绝。

最终结果应报告“**任务成功—用户负担—安全风险**”的 Pareto 关系，而不是只追求提问更少或服从率更高。一个安全系统不应盲目执行所有用户指令，一个高效系统也不应通过频繁打断用户来换取成功率。

## 7. 推荐的研究切入点

一个范围清晰、可验证的切入点是：

> 建立面向随时指导的混合主动权 VLN benchmark，统一建模智能体询问与人主动介入，并重点解决“介入意图识别—结构化空间落地—冲突检测—安全重规划”链条。

可以先限制在室内 ObjectNav 或长程任务导航中，选取五类人主动介入：补充、纠正、改目标、加约束和接管。基础实验可依次比较：

1. 只执行初始指令，不处理在线交互；
2. 只能由智能体提问；
3. 能接收人的主动指导，但不显式区分意图和冲突；
4. 完整的混合主动权模型；
5. 加入安全控制器、带噪用户和真人评测的完整系统。

核心贡献不应仅是生成更自然的话语，而应证明：

- 人和智能体都能在正确时机取得主动权；
- 指导能被转化为可验证的空间或任务约束；
- 新信息确实改变了信念和规划；
- 在固定用户负担下，任务成功率和失败恢复能力提高；
- 在冲突、延迟和危险情况下，系统仍能保持安全。

## 8. 总结

混合主动权把交互式 VLN 从“智能体会不会提问”推进到“人和智能体如何共同管理任务与控制权”。它要求系统同时支持智能体主动求助和人随时指导，并处理异步输入、意图变化、信息冲突、空间落地、安全重规划与控制权切换。

解决这一问题需要模块化的交互架构、分类型不确定性、基于信息价值的主动权策略、可验证的语言—空间表示以及独立的安全控制器。相应数据集必须记录在线、带时间戳的多模态轨迹，覆盖双方主动发起交互、人的不同介入类型、计划变化、控制权状态、用户噪声和安全事件。评价则应同时衡量任务效果、交互成本、指导落实、行为因果性、安全和人因体验。
